# 노드 시연 시나리오 (리더 층 Raft · 팀원 · 판정)

계획 8단계 체크리스트. 모든 단계는 `scripts/raft_nodes.py`(Windows: `scripts\raft-local.ps1`, macOS: `scripts/raft-local.sh`)
한 도구로 한다. `python scripts/raft_nodes.py scenario`는 ①~⑤를 빈 장부에서 자동으로 돌려 보고 통과 여부를 알려 준다
(2026-11-17 PC 1대 · 프로세스 9개로 통과).

## 0. 준비

```
gradlew :node:bootJar :fairchain:bootJar
```

| 구성 | 명령 |
|---|---|
| PC 1대에 전부 (프로세스 9개) | `python scripts/raft_nodes.py start --fresh` |
| PC 1대 = 팀 1개 (PC 3대 시연) | 각 PC에서 `python scripts/raft_nodes.py start --fresh --team A --host <이 PC IP> --leaders A1=http://<PC1>:9001,B1=http://<PC2>:9001,C1=http://<PC3>:9001` (팀 B · C도 같은 `--leaders`) |
| 순회 검사 켜기 (미정사항 12번) | `start`에 `--patrol` |
| 리더 소식 시간 제한 바꾸기 (미정사항 7번) | `start`에 `--heartbeat-timeout 3` (기본 4초) |

포트: 리더 층 9001~9003 (PC 3대면 각 PC 9001), 팀원은 팀마다 9011~ · 9021~ · 9031~. 다른 프로그램이 쓰는 포트는 건너뛴다
(이고르 노트북은 ASUS Armoury가 9012 · 9013을 써서 A3이 9014).

FairChain은 지금처럼 리더 층 주소만 안다: `--fairchain.nodes.urls=http://<PC1>:9001,http://<PC2>:9001,http://<PC3>:9001`.
노드 상태는 FairChain 시연 화면(`/demo.html`)과 점검 화면(`/inspector.html` → 블록체인 노드)에서 본다 — 역할 · 임기 ·
팀원 · 빠진 이유 · 판정 기록(#k → 제외 → 복귀). FairChain은 조회만 한다.

## 1. 체크리스트

| # | 할 일 | 명령 | 보이는 것 |
|---|---|---|---|
| ① | 기록 · 체크인 | FairChain에서 예매 · 체크인 (또는 `write 30`) | 리더 층 3대 · 팀원 6대의 마지막 해시가 같다. 팀원 블록의 서명자는 자기 팀 리더 |
| ② | 리더 끄기 | `kill-leader` | 새 리더 · 다음 기록까지 걸린 시간. 예전 리더는 `up <ID>`로 켜면 팔로워로 따라잡는다 |
| ③ | 팀 리더 장부 변조 (꼼꼼하게: 뒤 해시까지 다시 계산) | `tamper B1 --block 20 --rewrite` | 켤 때 서명 검사에서 걸림 → 스스로 빠짐 → 신고 → 판정: 처음 갈라진 블록 #20, 달라진 필드 recordHash · blockHash · signature → **제외** → #20부터 다시 받음 → **복귀**. 그동안 기록은 2대로 계속 |
| ③′ | 켜 둔 채로 FairChain 신고 흐름 | FairChain 체크인에서 소수 답 → 자동 신고 (`report B1`과 같음) | 리더가 해시 이진 탐색으로 #k를 찾는다 (블록 1만 개면 약 14번 요청) |
| ④ | 팀원 장부 변조 | `tamper A2 --block 10` | 팀원이 켤 때 검사에서 걸림 → 팀 리더 A1이 리더 층에 신고 → 같은 판정 · 제외 · 복구가 리더 층 Raft 로그에 기록 |
| ⑤ | 4번째 팀 가입 · 해지 | `join D1 --team D --port 9004` → `leave D1` | D1이 learner로 붙어 따라잡은 뒤 투표 멤버로 승격. 해지 뒤 3팀. 3팀에서 하나 더 빼면 "3개 미만" 거부 |
| ⑥ | (옵션) 키 유출 상황 | 테스트로만 재현 (`DivergenceTest`) | 서명이 둘 다 맞는 서로 다른 블록 → 기록 중단 → 관리자 `resume` |
| ⑦ | 장부 전체가 다른 노드 (#1부터) | `tamper C1 --block 1` | 자동 복구하지 않음 — "관리자: 해지 → 비우기 → learner로 재가입" (미정사항 11번) |

## 2. 말로 설명할 것 (발표)

- **합의는 노드 층에서**: FairChain은 아무 노드에나 기록을 보내고(팔로워는 리더에게 넘김), 판정도 노드가 한다. FairChain은 다른
  답을 한 노드를 신고만 한다 — FairChain 혼자서는 기관을 뺄 수 없다.
- **왕복 1번**: 리더가 팔로워 2대에 동시에 보내고 과반이 저장하면 확정 (예전: 제안 · 결정 · 확정을 이웃마다 차례로).
- **서명은 증거**: DB를 고친 사람이 해시를 처음부터 다시 맞춰도, 개인키(H2 밖 파일)가 없으면 서명을 못 만든다.
- **제외 ≠ 해지**: 제외된 노드는 멤버 명단에 남은 채 멈추고, #k부터 다시 받으면 복귀한다. 해지는 관리자가 명단에서 빼는 것.

## 3. 문제가 생기면

| 증상 | 확인 |
|---|---|
| 노드가 안 켜짐 | `data/raft/<ID>.log` |
| 리더가 계속 안 뽑힘 | 리더 층 3대 중 2대 이상 켜져 있는지 (`status`) |
| 예전 H2로 켰더니 바로 빠짐 | 서명이 없는 예전 장부 — `start --fresh`로 빈 장부에서 |
| 기록 중단 | `status`의 판정 기록 확인 → 원인을 치운 뒤 `resume` |
