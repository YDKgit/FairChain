# Blockchain v12 — Strict PREPARE gate

## Исправленная ошибка v11
`NodeService.submit()` раньше проверял `votes < 2`, хотя далее предполагал подтверждение всех трёх узлов. При одном отказе PREPARE координатор всё равно мог разослать COMMIT и вызвать частичную запись. В v12 переход к COMMIT допускается только после **трёх положительных PREPARE** (включая собственный голос координатора).

## Новые проверки
`NodePrepareQuorumTest.missingThirdPrepareMustNeverTriggerCommit`: два локальных HTTP mock-peer, один возвращает `true`, другой `false`. Тест проверяет, что coordinator не делает запросов `/confirm` и оставляет подготовленную запись.

## Известное ограничение
Подготовка всех узлов НЕ обеспечивает атомарного commit. При недоступности узла между PREPARE и COMMIT возможен частичный COMMIT. Автоматическое разрешение конфликтующих цепочек не включено. Кроме того, `synchronized` защищает лишь один JVM, а не несколько координаторов. Для полноценной распределённой гарантии потребуется журнал решений, единый лидер/эпохи и восстановление после сбоев. Нельзя утверждать об отказоустойчивости до интеграционных тестов.

## Команды
Windows: `gradlew.bat :node:test :fairchain:test`
Linux/macOS: `./gradlew :node:test :fairchain:test`

В среде сборки может отсутствовать Gradle дистрибутив; в этом случае тесты не являются выполненными.
