## 0. 바뀌는 점 요약

| 항목 | 지금 (`demo-page` A안) | 변경안 |
|---|---|---|
| 합의 방식 | 목록 첫 번째 노드가 제안 → 과반 확정 (선거 없음) | **MicroRaft를 우리 규칙에 맞게 고쳐서 사용** (리더 선거 · 임기 · 하트비트) |
| 구조 | 노드 3대 한 층 | **2층: 리더 층(팀 리더들) + 팀원 층(팀마다)** |
| 가입 단위 | 노드 (`NODE_PEERS` 수정 후 재시작) | **팀 단위 가입 · 해지, 재시작 없음** |
| 변조 점검 | 5초마다 전체 체인 검사 | **투표 · 조회 때 쓰인 블록이 다를 때만** 확인 + 켤 때 전체 검사 1번 |
| 누가 틀렸는지 | 모름 (`true/false`만 돌려줌) | **팀원은 팀 리더가, 리더는 리더들끼리 판정** |
| 위조 증명 | 없음 | **블록 전자서명 (Ed25519)** |
| 꺼졌다 켜진 노드 | 5초마다 다른 노드에서 가져옴 | 리더가 빠진 블록을 보내 줌 (Raft) |

## 1. 구조

```
FairChain
   │ 기록
   ▼
[리더 층]  팀A 리더 ─ 팀B 리더 ─ 팀C 리더      ← Raft 그룹 1개. 여기서 과반이면 확정
              │          │          │
[팀원 층]  팀A 팀원들  팀B 팀원들  팀C 팀원들   ← 팀마다 Raft 그룹 1개. 확정 블록을 받아 저장
```

- **팀 = 기관 하나.** 기관이 노드 여러 대를 운영한다.
- 팀 리더는 **리더 층 멤버이면서 자기 팀 그룹의 리더**다 (두 그룹에 동시에 속함).
- 리더 층에는 **노드가 아니라 팀(팀 ID + 대표 주소)**을 등록한다. 팀 리더가 바뀌어도 리더 층 설정은 그대로다.
- 리더 층 팀 수는 **3개 이상, 홀수 권장** (2:1 판정, 1팀 장애 허용).
- 팀원 수는 제한 없음 (팀원 판정은 다수결이 아니라 확정 블록 기준이므로).

---

## 2. 기록 흐름

```
① FairChain → 리더 층의 리더
② 리더 층 리더 → 다른 팀 리더들에게 블록 전송 → 과반 저장 → 확정 (리더가 블록에 서명)
③ FairChain에 응답  ← 여기까지가 FairChain이 기다리는 시간
④ 각 팀 리더 → 자기 팀원들에게 확정 블록 전송 → 팀원 과반 저장
```

- **확정은 ②에서 리더 층만으로 끝난다.** ④의 팀원 투표는 확정을 바꾸지 못하고, 팀 안에 사본을 저장하는 단계다.
- FairChain 응답 속도는 리더 층 Raft 한 번과 같다. 팀원이 늘어도 느려지지 않는다.
- 팀원 층도 같은 방식으로 투표한다. 리더가 이상한 블록을 보내면 팀원들이 거부하고, 그 거부가 리더 이상 신호가 된다.

## 3. 변조 · 불일치 처리

### 3-1. 언제 확인하나 (전체 비교를 계속 하지 않음)

| 시점 | 무엇을 비교 | 잡히는 것 |
|---|---|---|
| 투표할 때 | 마지막 블록 해시(prevBlockHash) | 기록을 바꾸고 뒤 해시까지 다시 계산한 변조 |
| 체크인 · 목록 조회할 때 | 그 블록의 티켓 해시(recordHash) | 해당 블록의 기록 변조 |
| 노드를 켤 때 (1번) | 체인 전체 해시 재계산 | 꺼져 있는 동안 DB를 고친 경우 |

### 3-2. 누가 판정하나

| 층 | 누가 발견 | 누가 판정 | 기준 |
|---|---|---|---|
| 팀원 | 팀 리더 (팀원 투표 거부 · 불일치) | **팀 리더** | 리더 층에서 확정된 블록. 리더와 다르면 팀원이 틀림 |
| 리더 | FairChain (체크인 · 조회 다수결에서 소수 발견) 또는 리더끼리 투표 중 | **리더들 과반** | 서명 검증 → 2:1 다수결 |

- **FairChain은 판정하지 않는다.** 소수인 리더를 발견하면 "리더C가 다르다"고 리더들에게 **알리기만** 한다.
  → FairChain 혼자서는 기관(팀)을 뺄 수 없다. 블록체인을 FairChain에서 분리한다는 A안 장점도 유지된다.
- 리더가 팀원을 거짓 판정할 걱정은 없다. 우리가 막는 것은 DB 변조이고, 리더 DB가 변조됐다면 리더 층에서 먼저 걸린다.

### 3-3. 판정 절차 (이고르 문서 방식)

1. **뒤처짐인지 갈라짐인지 구분**: 마지막 번호 · 해시 비교. 번호만 작으면 `BEHIND` → 빠진 블록 전송.
2. **갈라진 블록 찾기**: 해시 이진 탐색. 블록 1만 개면 약 14번 요청으로 #k를 찾는다.
3. **판정**: #k의 **서명 검증** → 서명이 안 맞는 쪽이 틀림. (서명 도입 전 블록이면 2:1 다수결)
4. **증거 저장**: #k의 두 버전, 달라진 필드(recordHash 등), 판정 시각을 기록한다.
5. **제외 · 복구**: 틀린 노드는 투표하지 않고 리더 후보도 되지 않는다. #k부터 지우고 다시 받은 뒤 복귀한다.
   - 틀린 노드가 리더 층 리더였다면 스스로 내려오고 새 리더를 뽑는다.
   - 틀린 노드가 팀 리더였다면 팀 안에서 새 리더를 뽑고, 새 리더는 **다른 팀 리더들에게서** 따라잡는다.

### 3-4. 거부 이유 코드 (지금 `peerPost`의 true/false를 대체)

| 코드 | 뜻 | 처리 |
|---|---|---|
| `STALE_TERM` | 더 새로운 리더가 있음 | 팔로워로 내려감 |
| `BEHIND` | 받는 쪽이 뒤처짐 | 빠진 블록 전송 |
| `DIVERGED` | 기록이 갈라짐 | 3-3 판정 절차 |
| `INVALID_BLOCK` | 블록 내용 · 서명이 틀림 | 경고 (버그 또는 변조) |
| `CHAIN_INVALID` | 받는 쪽 체인이 망가짐 | 복구될 때까지 제외 |
| `ALREADY_VOTED` | 그 번호에 이미 다른 블록에 투표함 | 끝나지 않은 라운드 마무리 |

## 4. 전자서명

- 각 노드가 키 쌍을 만든다 (Java 17 내장 **Ed25519**).
- **공개키는 팀 가입할 때 함께 등록**한다 (5장 가입 API).
- **확정 당시 리더 층 리더가 블록에 서명**한다. 팀원 · 다른 리더는 블록을 받을 때 서명을 검증한다.
- 효과
  - 1:1로 갈라져도 서명으로 판정할 수 있다 (다수결 불필요).
  - 과반이 변조돼도 리더의 개인키 없이는 맞는 서명을 만들 수 없다.
  - 사본 하나만 있어도 위조 여부를 알 수 있다.
- 투표 서명(이중 투표 증거)은 이번 범위에서 제외하고, 확장으로 설명한다.

---

## 5. 팀 가입 · 해지

- **가입**: 팀 ID, 대표 주소, 공개키를 리더 층에 등록 → Raft 멤버 변경으로 반영 (재시작 없음)
  1. 새 팀은 먼저 **learner**로 붙어 투표 없이 블록만 받는다.
  2. 다 따라잡으면 투표 멤버로 올린다.
  3. **한 번에 한 팀씩** 바꾼다.
- **해지**: Raft 멤버 변경으로 제외. 한 번에 한 팀씩.
- 팀원 가입 · 해지도 같은 방식으로 팀 그룹 안에서 한다.

---

## 6. 응답 없음 · 판정 불가

| 상황 | 처리 |
|---|---|
| 응답 없음, 과반 미달 | FairChain → 리더 재전송, 리더 → 팀원 재전송 |
| 재전송 계속 실패 | 정해진 횟수 뒤 FairChain에 실패 응답, 기록은 Redis 대기 줄에 다시 넣음 |
| 서로 다른 블록 (1:1 포함) | 서명 검증으로 판정 |
| 서명이 둘 다 맞는데 내용이 다름 (키 유출) | 기록 중단 + 관리자 확인 |

## 7. 아직 정하지 않은 것

| 항목 | 추천안 |
|---|---|
| **팀 해지 하한** | 팀 3개 미만이 되는 해지는 막는다 |
| 재전송 횟수 | 3번 |
| MicroRaft 라이선스 | 고쳐서 쓰므로 조건(출처 표기 등) 확인 필요 |

## 8. 구현 전에 확인할 것

- MicroRaft에 우리 규칙을 넣을 자리가 있는지
  - 블록을 받기 전에 내용 · 서명 검사
  - 거부가 쌓이면 리더 교체
  - 제외된 노드는 리더 후보가 되지 않기
- 한 노드가 Raft 그룹 2개(리더 층 + 팀)에 동시에 속할 수 있는지
- 지금 코드에서 1단계 개선(이웃 동시 전송, 왕복 3→2번) 후 속도 재측정 → 변경안과 비교 기준

## 9. 함께 바뀌어야 하는 것

- **FairChain**: 기록을 리더에게 보내기, 체크인 · 조회에서 소수 리더 알림, 노드 목록을 팀 단위로
- **시연 화면**: 리더 · 팀원 표시, 제외 · 복구 상태, 판정 과정(#k 불일치 → 판정 → 복구), 팀 추가 · 해지
- **설계명세서**: 노드 합의 시퀀스(SD-0302-03 등), 클래스 다이어그램
- **최종발표**: n² 질문 답변 — "지금은 O(n), 느렸던 건 순차 전송 때문. Raft를 참고해 개선했고, 팀 단위 2층으로 확장 가능"
