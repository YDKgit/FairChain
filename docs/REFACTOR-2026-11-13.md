# 리팩터링 2026-11-13 (FairChain 서버 · FairChain 화면 · 예제서버 · 예제서버 화면)

노드 서버(`node`, `node-api`)는 손대지 않았다 (이고르 담당). 동작은 그대로 두고 구조만 정리했고,
기존 테스트 36개(FairChain 23 · 예제서버 13)와 실제 기동 흐름(좌석 등록 → 대기열 → 예매 → 검증 → 게이트 → 매진 후 취소 → 재배정 제안 → 재배정 예매)을 확인했다.
커밋하지 않았다 — 이고르 · 종선 확인 뒤 올린다.

## fairchain-api (공용 계약)
| 위치 | 변경 | 이유 |
|---|---|---|
| `QueueStatusResponseDto` | 상태 상수 `WAITING · ADMITTED · EXPIRED · NOT_FOUND`와 `isWaiting()` 추가 | FairChain(`FC_QueueService`)과 예제서버(`QueueService`)가 각자 문자열을 들고 있던 것을 계약 한 곳으로 |
| `RestHttpRequester` | apiKey가 빈 문자열이면 null로 취급 | 두 서버의 Config가 같은 "빈 값 → null" 코드를 반복하던 것 제거 |

## FairChain 서버 (`fairchain`)
| 위치 | 변경 | 이유 |
|---|---|---|
| `reservation.service.EventFinder` (새 클래스) | 공연 조회 + 고객사 소유 확인(`owned` · `ownedForUpdate` · `checkOwner`) | `ReservationService`의 `ownedEvent/lockedEvent/checkOwner`와 `FC_QueueService.checkOwner`가 같은 규칙을 두 벌로 갖고 있었다. 컨트롤러가 `FC_QueueService.checkOwner`를 빌려 쓰던 교차 의존도 없앰 |
| `common.RedisKeys` (새 클래스) | Redis 키 이름 전부 + 시연용 초기화 패턴 목록 | 키 문자열이 6개 Repository와 `RedisResetOnStart`에 흩어져 있었다 |
| `common.SseSupport` (새 클래스) | SSE 연결 생성(끊김 정리) · 전송 실패 처리 | `FC_QueueController`와 `DashboardService`가 같은 onCompletion/onTimeout/onError · try-catch를 반복 |
| `common.GlobalExceptionHandler` · `ErrorResponse` | 깨진 JSON · 파라미터 오류 → 400, 없는 경로 → 404, 그 외 → 500(로그), SSE 타임아웃 → 503. 응답 본문은 `ErrorResponse(code, message)` record | FairChainException 외의 오류가 Spring 기본 HTML/빈 응답으로 나가던 것을 같은 JSON 모양으로 통일 |
| `common.ClientContext.find(request)` | 요청 속성에서 clientId 읽기 | `RequestLogFilter`가 속성 이름 문자열을 복사해 쓰던 것 제거 |
| `block.requester.NodeLedgerAccess` · `NodeLedgerRequester` (새) | 노드 원장 상태 · 블록 조회 | `DemoController`와 `InspectorService`가 각자 `List<HttpRequester>`를 돌며 같은 호출을 하던 것을 한 곳으로. 컨트롤러가 HTTP 부품을 직접 들지 않게 |
| `block.requester.Majority.quorum` | `(n*2+2)/3` (⌈2n/3⌉) | 같은 값, 식만 단순화 (MajorityTest 통과) |
| `AnchorRecord.confirm(Long)` | 삭제 | 쓰는 곳 없음 |
| `AnchorRecordRepository.findByClientIdOrderByIdDesc(…, Pageable)` · `AdmissionRepository.findByEventIdInOrderByIdDesc(…, Pageable)` | 점검 화면용 페이지 조회 | `InspectorService.db`가 테이블 전체를 읽어 메모리에서 거르던 것을 DB 조건 + 300건 제한으로 |
| `NodeConfig` | 빈 키 처리 코드 제거 | RestHttpRequester가 처리 |

이름은 설계서(클래스 다이어그램)의 것을 그대로 두었다 (`FC_QueueController` 등).
